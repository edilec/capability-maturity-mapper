# Capability Maturity Mapper documentation

The CLI takes `--root`, `--rubric` and `--evidence`; both JSON paths are relative to the real root. The rubric is `{schemaVersion:"1", capabilities:[{id,criteria:[{id,dimension,weight,maxAgeDays}]}]}`. A dimension is `repeatability`, `controls` or `recovery`; weight is 1–10; `maxAgeDays` is 0–3650. Capability and criterion IDs are unique, 1–80 characters of letters, digits, period, underscore or hyphen. The evidence export is `{schemaVersion:"1",assessedAt,records:[{criterionId,capturedAt,kind,outcome,artifact?}]}`. Times are exact UTC second timestamps. `kind` is `verified` or `self-rated`; `outcome` is `met` or `not-met`. Verified records require an artifact path to a regular file inside the real root. Self ratings carry no artifact and do not count as verification.

Each criterion must have one evidence record. Missing or duplicate records, self ratings, evidence captured after assessment, stale records, and missing or out-of-root artifacts yield `incomplete` and zero verified credit for that criterion. A documented `not-met` outcome is an evaluated failure (exit 1) and zero credit. The score is verified `met` weight divided by total rubric weight, rounded to two decimals. Assessment date comes from `assessedAt`; no wall clock is used for age. A tool cannot authenticate the artifact's claims or the person who classified its outcome.

stdout contains one JSON report: `schemaVersion`, `tool`, `status`, `summary`, sorted `findings`, and ordinal `capabilities` with score, assessmentDate, verifiedCriteria and totalCriteria. stderr contains a human summary. Findings sort by code unit on `(location.file, location.pointer, ruleId)`; `@rubric` and `@evidence` are logical roles and pointers locate the exact input field without exposing identifiers. Exit 0 is complete and met, 1 is a documented not-met criterion, 2 is incomplete evidence or invalid invocation. Invalid options or root yield empty stdout; input read/decode/parse failures yield an `incomplete` JSON report. Messages do not contain input values.

Bounds: 262144 bytes per JSON file, JSON container depth 4 (root at depth 0), 100 capabilities, 1000 criteria, 1000 evidence records and 5000 milliseconds from root resolution. N is accepted and N+1 is incomplete. The tool reads only the two inputs and referenced artifacts; it never writes, calls a provider, or treats input text as instructions.

Stable rules: `criterion-not-met` is error severity. `input-unavailable`, `input-invalid`, `input-too-large`, `depth-limit`, `record-limit`, `timeout`, `evidence-missing`, `evidence-stale`, `evidence-ambiguous`, `self-rating-unverified`, `artifact-unavailable`, `evidence-future` are warnings that force `incomplete`.
